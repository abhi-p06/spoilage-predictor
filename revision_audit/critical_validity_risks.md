# AgriRoute Critical Scientific & Validity Risks

> **Audit Date:** 2026-11-08  
> **Auditor:** Independent Research Auditor (AgriRoute Research Revision)  
> **Scope:** Scientific integrity, data provenance, evaluation methodology, and manuscript-code alignment

---

## Executive Assessment

The AgriRoute codebase represents an impressive engineering prototype of an agricultural decision-support web application. However, **the manuscript submitted for peer review contains severe scientific validity flaws, target leakage, ungrounded mathematical formulas, and unverified empirical claims**. 

Most critically, the reported **BiLSTM AUC=1.000 is an artifact of trivial synthetic data generation**, the **routing risk equation ($G$) in the manuscript does not exist in the codebase**, the **case-study mandi price was generated by an offline MD5 hash rather than a live government API**, and **two of the four claimed produce species (Tomato, Mango) were never present in the image training dataset**.

If presented to reviewers without radical correction, these discrepancies represent fatal grounds for immediate rejection under scientific integrity standards.

## The Five Highest-Risk Issues

### Risk 1: Artificial Target Leakage in Synthetic Sensor Generation Yielding Trivial BiLSTM AUC=1.000

- **Exact Location:** `generate_sensor_data.py` (lines 68–87), `logs/lstm_training.log` (lines 57–66, 105–125), `notebooks/02_lstm_training.py` (lines 85–117).
- **The Mechanism:**
  In `generate_sensor_data.py`, lines 68–80 define how sensor readings are generated for spoiled vs fresh samples:
  ```python
  if spoiled:
      ethylene    = rng.uniform(eth_high * 0.6, eth_high, HOURS) + rng.normal(0, 1.5, HOURS)
      co2         = rng.uniform(1000, 3000, HOURS) + np.linspace(0, 500, HOURS) + rng.normal(0, 80, HOURS)
      humidity    = rng.uniform(85, 98, HOURS) + rng.normal(0, 1.5, HOURS)
      temperature = rng.uniform(20, 30, HOURS) + rng.normal(0, 0.8, HOURS)
      label = 1
  else:
      ethylene    = rng.uniform(eth_low, eth_low * 4, HOURS) + rng.normal(0, 0.5, HOURS)
      co2         = rng.uniform(400, 900, HOURS) + rng.normal(0, 40, HOURS)
      humidity    = rng.uniform(65, 85, HOURS) + rng.normal(0, 1.0, HOURS)
      temperature = rng.uniform(10, 22, HOURS) + rng.normal(0, 0.5, HOURS)
      label = 0
  ```
  - **Disjoint Distributions:** The CO₂ concentration for fresh produce is bounded in $[400, 900]$ ppm, whereas for spoiled produce it is bounded in $[1000, 3500]$ ppm. There is **zero overlap**.
  - **Zero-Variance Separation:** Humidity for fresh is $\le 85\%$, while for spoiled it is $\ge 85\%$. Temperature for fresh is $[10, 22]^\circ\text{C}$ vs spoiled $[20, 30]^\circ\text{C}$.
  - **Consequence:** Any elementary decision stump (`if co2 > 950: return spoiled`) achieves 100.0% accuracy on every split. The 2-layer Bidirectional LSTM with 309,633 parameters achieves `val_auc = 1.000` on **Epoch 1** (`logs/lstm_training.log` line 59) because the classification problem is mathematically trivial.
  - **Scientific Risk:** Claiming that a model achieves "AUC=1.000" on synthetic data created by the authors with linearly separable distributions is fatal. Any peer reviewer in machine learning will instantly identify this as synthetic target leakage.

### Risk 2: Ghost Mathematics in the Manuscript vs. Codebase Reality

- **Exact Location:** `~/Downloads/main.tex` (lines 204–218, 241–266), `app/app.py` (lines 180–205), `app/predict.py` (lines 249–297).
- **The Mechanism:**
  - In `main.tex`, Section VI-B and VI-C define the system's core mathematical model:
    $$\text{Eq. (2): } G = \operatorname{clip}(\alpha \tau D - \beta c, 0, 100)$$
    $$\text{Eq. (3): } S = w_1 V + w_2 G, \quad w_1 + w_2 = 1$$
  - In `main.tex`, Section VII-A claims: *"In the illustrative case study of Section VII-A, $V = 65.3$ and $G = 31.5$ combine to $S = 34.7$; because that result sits closer to $G$ than to $V$, the route-risk term is the larger contributor to $S$ on this run..."*
  - **Discrepancy with Code:**
    1. Neither Eq. (2) nor Eq. (3) exists anywhere in the codebase.
    2. In `app/app.py` line 183, `distance_km` ($D$) is parsed from the form, but line 200 calls `run_prediction(image_path, produce, days, cold_chain)`. **`distance_km` is never passed into the prediction function!** Transport distance has 0.0% impact on the prediction output.
    3. Production inference in `app/predict.py` uses an XGBoost classifier/regressor or a fallback formula:
       $$\text{spoilage} = 0.45(1 - \text{cnn}) + 0.40(\text{lstm}) + 0.15(\text{days}/\text{shelf})$$
    4. The parameters $\alpha, \beta, \tau, w_1, w_2$ are entirely fictional and referenced 6 times in `main.tex` as *"pending confirmation in Table V"*. Table V was never created.
  - **Scientific Risk:** Fabricating equations and illustrative numbers that do not match the software execution violates fundamental research integrity standards.

### Risk 3: Case Study Mandi Price Claimed as Live AGMARKNET Pull but Generated by Offline MD5 Hash Fallback

- **Exact Location:** `~/Downloads/main.tex` (lines 193, 261–266), `app/app.py` (lines 90–126), `app/mandi_prices.py` (lines 83–86, 178–197).
- **The Mechanism:**
  - `main.tex` line 193 states: *"Price information is deliberately not cached from a static, training-time snapshot --- the destination mandi's recent daily price series is pulled from AGMARKNET at request time, so the trend a farmer sees reflects the market as it stands that day rather than a stale average baked in months earlier."*
  - `main.tex` Section VII-A reports: *"alongside a falling price trend (Rs. 1803 $\to$ Rs. 1767/quintal over three days) that independently triggered a Sell Now flag..."*
  - **Discrepancy with Code:**
    In `app/app.py`, lines 90–97 define `_build_estimated_mandi(produce, destination)`:
    ```python
    seed = int(hashlib.md5(f"{produce}{destination}".encode()).hexdigest(), 16)
    base_prices = {"tomato": 1650, "apple": 4200, "banana": 1800, "mango": 3500}
    base = base_prices.get(produce.lower(), 2000)
    rng  = (seed % 300) - 150
    current = base + rng
    slope   = (seed % 30) - 15
    ```
    For `produce="banana"` and `destination="Rajkot"`:
    - `seed = md5("bananaRajkot")`
    - `current = 1800 + (seed % 300) - 150 = 1803`
    - `slope = (seed % 30) - 15 = -12`
    - 3-day forecast: $1803 - 12 = 1791$, $1803 - 24 = 1779$, $1803 - 36 = 1767$.
  - **Finding:** The exact price numbers reported in the paper (1803 $\to$ 1767) were generated by the **offline MD5 heuristic fallback**, because the author ran the case study without a `DATA_GOV_API_KEY`.
  - **Scientific Risk:** Claiming an output was fetched live from a government API when it was generated by an offline MD5 pseudo-random hash is a direct misrepresentation of experimental reality.

### Risk 4: Severe Produce Species Mismatch and Complete Lack of Tomato / Mango Training

- **Exact Location:** `README.md` (lines 191–199), `reports/pitch_preparation.md` (lines 50, 130), `notebooks/01_cnn_training.py` (lines 12–18, 92–112), `~/Downloads/main.tex` (lines 54, 71, 145).
- **The Mechanism:**
  - AgriRoute claims in the paper, README, and web app to support four agricultural commodities: **Apple, Banana, Tomato, and Mango**.
  - In `notebooks/01_cnn_training.py`, the training directory is populated from Kaggle `sriramr/fruits-fresh-and-rotten-for-classification`:
    ```
    freshapples (1,693), freshbanana (1,581), freshoranges (1,466)
    rottenapples (2,342), rottenbanana (2,224), rottenoranges (1,595)
    ```
  - **Tomato and Mango are completely absent from the dataset.** The author fine-tuned MobileNetV2 on Apples, Bananas, and Oranges, discarded Oranges from the web app, and added Tomato and Mango to the dropdowns without any training images.
  - In `reports/pitch_preparation.md` line 50, the author openly acknowledged: *"The model had never seen tomato or mango images during training — only apples, bananas, and oranges."*
  - **Scientific Risk:** Deploying a vision classifier on crop species it has never seen (out-of-distribution) and presenting it as a valid 4-crop tool is unscientific and guarantees real-world failure.

### Risk 5: Image Split Leakage, Crash in Evaluation Script, and Missing Model Checkpoints

- **Exact Location:** `notebooks/01_cnn_training.py` (lines 130–145, 396), `logs/cnn_training.log` (git commit `0af3146`), `git log` (commit `568fd60`).
- **The Mechanism:**
  1. **Split Leakage:** The CNN training script directly used Kaggle's pre-divided `train/` and `test/` folders. This public dataset contains video frame grabs and duplicate instances of the same fruit across folders. Without a group-aware split (partitioning by fruit batch, background, or harvest lot), test set evaluation suffers from identity leakage.
  2. **Evaluation Crash:** In `notebooks/01_cnn_training.py`, line 396:
     ```python
     val_acc = dict(zip(metrics_names, test_results))["accuracy"]
     ```
     Under Keras 3.x, `model.evaluate()` returned the metric key `compile_metrics` instead of `accuracy`. The script crashed with `KeyError: 'accuracy'` before generating per-class precision, recall, F1-scores, or confusion matrices. The "97.22%" reported in the paper is merely the global `compile_metrics` scalar from Epoch 5.
  3. **Deleted Model Weights:** In git commit `568fd60`, the author deleted `models/cnn_freshness.keras`, `models/lstm_spoilage.keras`, and `models/lstm_scaler.pkl`. As of today, running `python app/app.py` runs 100% on fallback heuristics because no model files exist on disk.
  4. **Synthetic Fusion Training:** In `notebooks/03_fusion_training.py`, the XGBoost model was trained on 10,000 synthetic rows where CNN freshness was generated by `rng.beta(7, 2)` or `rng.beta(2, 7)` because `cnn_freshness.keras` was missing during notebook execution (`logs/fusion_training.log` line 3: *"CNN model: ⚠️ not found — will simulate CNN outputs"*).
